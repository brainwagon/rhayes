# Rhayes Project Context

## Project Overview
**Rhayes** is a REYES-style (Render Everything You Ever Saw) software renderer written in strict C99. It implements a significant subset of the RenderMan Interface Specification (RISPEC). The project emphasizes portability, having no external dependencies beyond the standard C library (and `lodepng`, which is included).

## Building and Running

### Build System
The project uses a standard `Makefile`.

*   **Build All:** `make`
    *   Creates executables in `bin/` and `rhayes` in root.
    *   Creates static libraries in `lib/`.
*   **Clean:** `make clean`
*   **Test:** `make test`
*   **Profile:** `make profile` (Builds with `gprof` support)

### Key Executables
*   `rhayes`: Standalone demo executable (renders a built-in teapot scene).
*   `bin/render`: Main RIB renderer. Usage: `./bin/render input.rib`
*   `bin/catrib`: RIB parser/serializer utility (useful for debugging/formatting).
*   `bin/scene2rib`: Converts the C API scene (from `main_rib.c`) to RIB format.

## Project Structure

*   `src/`: Core source code.
    *   `rh_*`: Core rendering library (math, geometry, rasterization).
    *   `ri_*`: RenderMan Interface (API) implementation.
    *   `rib_*`: RIB parsing and output.
    *   `main.c`: Entry point for the standalone demo (`rhayes`).
    *   `render.c`: Entry point for the RIB renderer (`bin/render`).
*   `include/`: Header files (`ri.h` is the public API).
*   `tests/`: Integration tests.
    *   `rib/`: Test scenes in RIB format.
    *   `reference/`: Expected output images.
    *   `run_tests.sh`: Test runner script.
*   `lib/`: Compiled static libraries (`librh.a`, `libri.a`, `librib.a`).
*   `bin/`: Compiled executables.
*   `obj/`: Intermediate object files.

## Development Conventions

*   **Language:** Strict C99.
*   **Style:** Follows K&R or similar C conventions found in existing files.
*   **Libraries:**
    *   `librh`: Core rendering functionality (rasterizer, math, image buffers).
    *   `libri`: The RenderMan API implementation (state machine, attributes).
    *   `librib`: RIB generation.
    *   `libribparse`: RIB parsing.
*   **Testing:**
    *   Integration tests are preferred.
    *   Tests run by rendering `.rib` files and comparing output to `reference/*.png`.
    *   `run_tests.sh` handles parsing, rendering, and round-trip verification.
