# RenderMan Interface Specification 3.1: Variable Declaration and Handling

## Overview
This document outlines the handling of user-defined variables via `RiDeclare` in a RISpec 3.1 compliant renderer. It details variable types, storage classes (interpolation), and the algorithmic requirements for Splitting (decomposition) and Dicing (tessellation).

## 1. The RiDeclare Mechanism
`RiDeclare` associates a string token with a specific type and storage class. This allows the renderer to parse arbitrary data lists passed to geometric primitives.

**Function Signature:**
```c
RiDeclare(char *name, char *declaration);

```

* **name**: The token used in parameter lists (e.g., `"temperature"`).
* **declaration**: A string defining scope and type (e.g., `"varying float"`).
* **Default Scope**: If no class is provided, `uniform` is assumed (though `constant` is standard for non-geometric calls).
* **Default Type**: If no type is provided, `float` is assumed.

## 3. Storage Classes (Interpolation & Scope)

The storage class dictates the data frequency (how many values per primitive) and the interpolation method during sampling.

### A. `constant`

* **Definition:** One value per geometric primitive.
* **Semantics:** The value is constant across the entire surface.
* **Splitting:** Value is **copied** to all children.
* **Dicing:** The resulting grid inherits the single value.

### B. `uniform`

* **Definition:** One value per "face" or "micropolygon source".
* *Polygons:* 1 per polygon face.
* *Patches:* 1 per patch segment (e.g., 1 value for a bicubic patch defined by 16 points).


* **Semantics:** Piecewise constant. No interpolation occurs within the face.
* **Splitting:**
* *Face Split:* If a mesh is split into faces, values are distributed.
* *Geometry Split:* If a single patch is split (e.g., De Casteljau), the value is **copied** to both children.


* **Dicing:** The resulting grid inherits the single value of the source face.

### C. `varying`

* **Definition:** One value per parametric corner/vertex of the primitive.
* *Polygons:* 1 per vertex.
* *Patches:* 4 values per patch segment (corresponding to  corners: ).


* **Semantics:** **Bilinear interpolation** (or Linear for curves). It ignores the surface basis function.
* **Splitting:** New edge/center values are calculated via linear/bilinear interpolation.
* *Formula:* `new_val = 0.5 * (val_a + val_b)`


* **Dicing:** The 4 corner values are bilinearly interpolated to fill the  grid.

### D. `vertex`

* **Definition:** One value per control vertex (CV).
* *Polygons:* 1 per vertex.
* *Patches:* Matches the number of CVs (e.g., 16 for Bicubic, 4 for Bilinear).


* **Semantics:** Interpolated using the **surface basis function** (Bezier, B-Spline, etc.). The data "moves" exactly as the surface geometry `P` moves.
* **Splitting:** Must use the specific subdivision algorithm of the primitive (e.g., De Casteljau for Bezier, Cox-de Boor for B-Spline).
* **Dicing:** The grid values are generated by evaluating the basis function at every grid point .

When converting a final sub-patch into a Micropolygon Grid ( points):

1. **Allocate Grid Memory:** Size depends on data type (e.g., `float` grid vs `color` grid).
2. **If `constant` / `uniform`:**
* Fill entire grid with the single input value.


3. **If `varying`:**
* Input: 4 float values (corners).

4. **If `vertex`:**
* Input: Array of Control Vertex values (e.g., 16 floats).
* Operation: Run Basis Evaluation loop (e.g., `EvaluateBicubic(u, v, control_vals)`).
